# Betflow Analysis — dashboard

An interactive read-out of the Task 1 betting-flow analysis. It presents the
findings a trading desk would ask for — where the flow goes, when it arrives,
how it was priced, how concentrated it is, what the anomaly detectors flagged,
and which customers are statistically sharp — and lets every headline number be
traced back to the rows behind it.

## How it fits together

The dashboard renders **one artifact and computes nothing of its own.** The
Python pipeline (`../src`) does all the analysis and emits a single
`src/data/payload.json`; this app is a typed view over that file. If a number
looks wrong, it is a pipeline question, not a component one — the split is
deliberate, so the figures on screen are exactly the figures the pipeline
validated (the footer carries the dataset fingerprint and payload hash to prove
it).

```
../src (Python)  ──build_payload──▶  src/data/payload.json  ──▶  this app
```

To regenerate the payload after changing the analysis:

```bash
cd ..                       # task-1-betflow
python -m src.pipeline      # writes dashboard/src/data/payload.json
```

## Design

Everything visual derives from two tracked documents at the repo root:
`PRODUCT.md` (who this is for and why) and `DESIGN.md` (the palette, typography
and principles, including the colour-vision validation of the series palette
against the dark surface). `src/index.css` and `src/theme/echarts.ts` are two
renderings of the same DESIGN.md tokens — CSS custom properties for the DOM,
literal hex for the ECharts canvas, which cannot resolve `var(--…)`.

Charts are a deliberate hybrid:

- **ECharts** for standard forms (Lorenz curves, the value histogram, the timing
  phase columns, the daily activity bars) via a single registered theme, so no
  chart ever carries its own styling and none reads as a stock ECharts widget.
- **Hand-built SVG** for the two signature charts — the sharp-behaviour scatter
  (nearest-point hover, flag rings, verify halo) and the flow bar-table — where
  the reading, not just the plot, is the point.

## Verification

The report's first principle is that no claim is made without a path to its
evidence. Findings carry a `verify_ref`; a **Verify** control scrolls to the
backing table or chart and outlines the exact rows or point behind the number.
`resolveRef` in `src/lib/payload.ts` mirrors `resolve_ref` in the pipeline, so
the front end and the pipeline agree on what a reference resolves to.

## Deployment

`.github/workflows/deploy-dashboard.yml` (at the repo root) builds this
directory and publishes `dist/` to GitHub Pages on pushes to `main`. The Vite
`base` is relative, so the same build works from a Pages project subpath or a
custom domain with no reconfiguration. The site is fully static — the payload is
baked into the bundle, so there is no backend to run.

## Layout

```
src/
  data/payload.json      the analysis artifact (a build input; regenerated by the pipeline)
  lib/                   typed payload contract + formatting helpers (no arithmetic)
  theme/echarts.ts       the one ECharts theme, DESIGN.md tokens as literal hex
  charts/                Chart wrapper, ECharts charts, signature SVG charts
  components/            layout shell, tables, notes, stats, verify wiring
  sections/              one component per report section
  App.tsx                assembles the sections in reading order
```
